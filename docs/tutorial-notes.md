## Problems found

- [x] **FIXED (2026-10-09, uncommitted): the three freezes.** Reproduced on the owner's PC by driving the window's own commands, then fixed:
  - **Plugins (instrument and effect):** a self-deadlock on the window thread. `load_plugin` / `add_plugin_effect` ran on the window thread and synced the engine while holding its `synced` lock; the engine queued the plugin load with `main_thread::post_later`, but Tauri's `run_on_main_thread` runs a job *at once* when called from the main thread, so the load tried to take the same lock and waited forever (before Surge's code ever ran: no Surge DLL in Windows' hang reports). Fix: `post_later` now always queues (via a relay thread); the plugin commands are async. Test: `crates/daw-engine/tests/plugin_load_from_main_thread.rs`.
  - **Microphone / audio tracks / Audio tab:** `input_status` kept the `input` lock while calling `recording_delay`, which locks `input` again: every meter poll froze the app, with or without the headset. Fix: read and release; device opening no longer holds the lock; mic and output opens time out after 8 s with "Microphone unavailable: ..."; device commands are async; the input list is cached for 3 s. Tests: `the_microphone_meter_does_not_freeze` (app crate; its tests now start on Windows thanks to the manifest in `build.rs`) and `a_device_that_never_answers_gives_up_instead_of_freezing`.
  - **Why Surge was offered again after each freeze:** the background plugin scan at every start called `unblock_all`, wiping `plugins-switched-off.json`. Now only **Look for new plugins** retries switched-off plugins. Test: `a_plugin_that_froze_the_app_stays_off_after_the_startup_scan`.
