# Tempo map: implementation plan

Spec: `docs/superpowers/specs/2026-10-16-tempo-map-design.md`. Test-first:
each step starts with a failing test.

1. **Model** (`daw-model`)
   - `tempo.rs`: `TempoChange`, `TempoMap` (segments, `seconds_at`,
     `beats_at`, `bpm_at`, `next_change_after`, `is_steady`). Tests: steady
     map matches `60/bpm`; step and ramp round-trips; negative beats.
   - `Project.tempo_changes`, `SongState.tempo_changes`, `tempo_map()`,
     ids in `all_ids`/`id_in_use`, freeze fingerprint, file validation.
   - Commands `AddTempoChange`, `MoveTempoChange`, `SetTempoChange`,
     `RemoveTempoChange`, `RestoreTempoChange`; coalescing; JSON round-trip
     and apply/undo tests; old project JSON loads unchanged.
   - Audio clip helpers use the map (`natural_length_beats`, split, trim).
   - Summary: `tempo_changes` in `get_song`.
2. **Engine** (`daw-engine`)
   - `SetTempoMap(Box<TempoMap>)` replaces `SetTempo`; garbage variant.
   - Processor: per-segment rate from the map, stops at changes, ramp
     chunks, count-in tempo, effect/plugin `set_tempo` on change.
   - Audio regions in seconds; tempo-following clips cut per stretch.
   - Offline render lengths from the map.
   - Tests: headless render with a click per beat across a change lands at
     the right samples; ramp lands where the map says; audio clip keeps its
     speed across a change; `no_alloc` plays across a change and a ramp and
     swaps the map.
3. **Control/export/analysis/notation**
   - `place_take` with the map; game preview fade.
   - Export: frames from the map; Godot average bpm; docs.
   - Analysis `Timing` holds a map.
   - MIDI and MusicXML tempo events both ways; `import_song` adds changes.
4. **MCP**: tool descriptions from doc comments; stdio e2e test adds a
   change and reads it back from `get_song`.
5. **UI**: `types.ts`, `tempo.ts` (+ vitest), `preview.ts` cases, tempo
   strip in `Timeline.tsx`, audio clip drawing.
6. **Docs** and PLAN item 9; run every check; commit.
